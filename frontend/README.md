# KIT — KROK insight tool

React-приложение для работы с корпоративными отношениями. Начальная страница — обзор портфеля; из компании доступны карта связей, контакты, общая история и аналитика. Навигация сохраняется в URL и поддерживает обновление страницы и кнопки браузера.

## Запуск демо без Java и Docker

Нужен Node.js 22.13+ (рекомендуется актуальная LTS). Из `frontend/`:

```sh
npm ci
npm run build
npm run demo
```

Открыть [KIT](http://127.0.0.1:5173/). Сервер привязан только к `127.0.0.1`. Демоданные берутся из SQL-файлов команды в `backend/src/main/resources/db/demo`. Первое открытие создаёт SQLite в `frontend/.data/kit.sqlite`; встречи и версии позиций сохраняются между обновлениями страницы и перезапусками сервера. Эта папка исключена из Git. Для отдельной базы можно задать `CROC_DEMO_DATA_DIR`. Для смены порта — `PORT`.

Демо явно отмечено в интерфейсе, содержит синтетические компании и адреса `.example`. Это самостоятельный локальный источник для MVP, без интеграции с корпоративной CRM. Сброс данных: остановить сервер и удалить `.data/kit.sqlite` вместе с файлами `-wal` и `-shm`, если они есть. Удаление базы удаляет и введённые записи.

## Работа с API команды

1. Запустить [Spring Boot API](../backend/README.md) с миграцией V5 и профилем `demo`.
2. Для сохранения взаимодействий и позиций подготовить деморедактора по инструкции бэкенда. После обновления до V5 повторно выполнить `docker/postgres/provision-writer.sql`.
3. Запустить `npm run dev`. Локальный демосервер на том же порту должен быть остановлен.

Vite берёт пароли из `backend/.env` на стороне сервера. Маршруты событий, разрешений и тестового источника используют деморедактора, если он настроен; остальные запросы используют читателя. Пароли не передаются в JS-сборку. Без редактора приложение доступно для чтения, кнопка создания взаимодействия отключена. `/capabilities` определяет доступные действия.

## Пользовательский сценарий

1. В «Обзоре» посмотреть число компаний, уникальных сотрудников, взаимодействий за 30 дней до среза и сигналов по инициативам.
2. Открыть «Северную линию». В карточке компании видны её описание, подразделения, ключевые ЛПР и история по всем инициативам.
3. Открыть карту, выбрать инициативу и роль «Утверждает бюджет», нажать на Марину Орлову, затем «Окружение выбранного». На небольшом экране сначала закрыть профиль: выбранный контакт остаётся выделенным.
4. В профиле посмотреть роль, контактные данные, оценку влияния с основанием, позицию и версии. Перейти к связанному сотруднику или открыть редактор позиции в источнике.
5. В истории добавить встречу, звонок, письмо, комментарий или предложение. Указать участников, дату, команду, ответственного, результат и следующий шаг. После сохранения обновляются история, охват и аналитика.

## Функции и правила данных

- Поиск по платформе находит компании и людей. Семь фильтров контактов и карты сочетаются: поиск, роль, подразделение, должность, влияние, наличие/давность касаний, ответственный менеджер.
- Роль, влияние и позиция относятся к конкретной инициативе. Цвет карточки обозначает роль, размер слегка меняется по явно указанной оценке влияния. Неизвестные данные показываются как неизвестные.
- Стрелки сохраняют направление `source → target`; пунктир обозначает неподтверждённую связь. Текстовое описание доступно под картой и в профиле. Окружение показывает прямые входящие и исходящие связи, сбрасывая остальные фильтры.
- История компании объединяет все инициативы, поддерживает поиск, фильтры и показ дополнительных записей. Автор записи назначается сервером, ответственный менеджер указывается в форме.
- Добавление взаимодействия атомарно. ID запроса предотвращает дублирование при повторе после сетевой ошибки. Форма сохраняет черновик при ошибке. Будущие даты, пустые поля, повторяющиеся и чужие участники отклоняются сервером. Запросы записи защищены CSRF.
- Индекс в аналитике: `round(50 × recentDecisionMakers / decisionMakers + 30 × activeDepartments / departments + 20 × verifiedDecisionMakers / decisionMakers)`. Он описывает полноту зафиксированного охвата и рассчитывается до фильтрации. При неизвестных ЛПР или подразделениях оценка не выставляется. Порог проверки контактов берётся из API (90 дней).
- Рекомендации по данным используют явные правила. AI-навигатор подключается отдельно через локальную модель на Spring Boot по [инструкции](../backend/README.md#локальный-навигатор). В SQLite-демо генерация AI-ответов отключена.
- Полноценная CRM-синхронизация, автоматические уведомления и многопользовательское совместное редактирование остаются за рамками MVP. Добавление компаний и контактов выполняется в исходном источнике.

## Проверки

```sh
npm test
npm run build
```

Тесты проверяют фильтры и окружение, направление связей, расчёт охвата и индекса, уникальные контакты, пагинацию, запись/перезапуск SQLite, идемпотентность, права CSRF и валидацию HTTP. Для тестов нужно разрешить локальные порты. Kotlin-интеграционные тесты используют PostgreSQL через Docker/Testcontainers.
