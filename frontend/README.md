# KIT — KROK insight tool

React-приложение для работы с корпоративными отношениями. Начальная страница — обзор портфеля; из компании доступны карта связей, контакты, общая история и аналитика. Навигация сохраняется в URL и поддерживает обновление страницы и кнопки браузера.

## Запуск демо без Java и Docker

Нужен Node.js 22.13+ (рекомендуется актуальная LTS). Из `frontend/`:

```sh
npm ci
npm run build
npm run demo
```

Открыть [KIT](http://127.0.0.1:5173/). Сервер привязан только к `127.0.0.1`. Демоданные берутся из SQL-файлов команды в `backend/src/main/resources/db/demo`. Первое открытие создаёт SQLite в `frontend/.data/kit.sqlite`; встречи и версии позиций сохраняются между обновлениями страницы и перезапусками сервера. Эта папка исключена из Git. Для отдельной базы можно задать `CROC_DEMO_DATA_DIR`. Для смены порта — `PORT`.

Демо явно отмечено в интерфейсе, содержит синтетические компании и адреса `.example`. Это самостоятельный локальный источник для MVP, без интеграции с корпоративной CRM. Сброс данных: остановить сервер и удалить `.data/kit.sqlite` вместе с файлами `-wal` и `-shm`, если они есть. Удаление базы удаляет и введённые записи.

## Работа с API команды

1. Запустить [Spring Boot API](../backend/README.md) с профилем `demo` и применить миграции до V7.
2. Для сохранения взаимодействий и позиций подготовить деморедактора по инструкции бэкенда. При обновлении повторно выполнить `docker/postgres/provision-writer.sql`.
3. Запустить `npm run dev`. Локальный демосервер на том же порту должен быть остановлен.

Vite берёт пароли из `backend/.env` на стороне сервера. Все запросы используют одну учётную запись, редактора при его наличии или читателя. Пароли не передаются в JS-сборку. `/capabilities` определяет доступные действия. Обзор использует `/dashboard`, а детали и граф проекта загружаются по мере открытия разделов.

## Пользовательский сценарий

1. В «Обзоре» посмотреть число компаний, уникальных сотрудников, взаимодействий за 30 дней до среза и сигналов по инициативам.
2. Открыть «Северную линию». В карточке компании видны её описание, подразделения, ключевые ЛПР и история по всем инициативам.
3. Открыть карту, выбрать проект и воспользоваться поиском или фильтром «Только ЛПР». Одно нажатие на узел или имя открывает профиль. Кнопка «К карте связей» возвращает к выбранному участнику и восстанавливает глубину окружения.
4. В профиле посмотреть роль, контактные данные, оценку влияния с основанием, позицию и версии. Перейти к связанному сотруднику или открыть редактор позиции в источнике.
5. В истории добавить встречу, звонок, письмо, комментарий или предложение. Указать участников, дату, команду, ответственного, результат и следующий шаг. После сохранения обновляются история, охват и аналитика.

## Функции и правила данных

- Поиск по платформе находит компании и людей. Семь фильтров контактов и карты сочетаются: поиск, роль, подразделение, должность, влияние, наличие/давность касаний, ответственный менеджер.
- Роль, влияние и позиция относятся к конкретной инициативе. Цвет карточки обозначает роль, размер слегка меняется по явно указанной оценке влияния. Неизвестные данные показываются как неизвестные.
- Стрелки сохраняют направление `source → target`; пунктир обозначает неподтверждённую связь. Текстовое описание доступно под картой и в профиле. Окружение показывает прямые входящие и исходящие связи, сбрасывая остальные фильтры.
- История компании объединяет все инициативы, поддерживает поиск, фильтры и показ дополнительных записей. Автор записи назначается сервером, ответственный менеджер указывается в форме.
- Добавление взаимодействия атомарно. ID запроса предотвращает дублирование при повторе после сетевой ошибки. Форма сохраняет черновик при ошибке. Будущие даты, пустые поля, повторяющиеся и чужие участники отклоняются сервером. Запросы записи защищены CSRF.
- Индекс в аналитике: `round(50 × recentDecisionMakers / decisionMakers + 30 × activeDepartments / departments + 20 × verifiedDecisionMakers / decisionMakers)`. Он описывает полноту зафиксированного охвата и рассчитывается до фильтрации. Когда по одному из показателей нет ни одной известной записи, оценка не выставляется. Порог проверки контактов берётся из API (90 дней).
- «Аналитика» использует серверный индекс проекта и сигналы риска по компании. Модель для рекомендаций по компании или проекту подключается в боковом разделе «Настройки ИИ». Поддерживаются локальный сервер и внешний API с ключом. [Настройки ИИ](../backend/README.md#настройки-ии)

## Проверки

```sh
npm test
npm run build
```

Тесты проверяют фильтры и окружение, направление связей, расчёт охвата и индекса, уникальные контакты, пагинацию, запись/перезапуск SQLite, идемпотентность, права CSRF и валидацию HTTP. Для тестов нужно разрешить локальные порты. Kotlin-интеграционные тесты используют PostgreSQL через Docker/Testcontainers.

## Карта связей

Карта использует `react-force-graph-2d`. Узлы можно перетаскивать и закреплять. Доступны масштабирование, подбор масштаба, сброс расположения, пауза и цвет по роли или отделу. Поиск и фильтры расположены над полотном, сведения о карте и участники — в отдельной боковой панели. В профиле граф окружения расположен слева, сведения о человеке справа.

По наведению подсвечиваются ближайшие соседи по входящим и исходящим связям. Подписи ЛПР остаются видимыми при отдалении и выключении обычных подписей. Цвет линии обозначает тип связи, пунктир — неподтверждённую связь. Нажатие на линию в карте проекта открывает описание в боковой панели. Окружение раскрывается на один или два шага.

Размер соответствует оценке влияния из источника. Библиотека меняет копии данных, исходный ответ API не изменяется. Координаты сохраняются при фильтрации в пределах открытой карты. Адаптер проверен набором 480 узлов / 579 рёбер. [Лицензии](THIRD_PARTY_NOTICES.md).

## Импорт контактов из CRM

Кнопка «Импорт CSV» открывает импорт выгрузки с предпросмотром. UTF-8, запятая или точка с запятой, до 500 контактов и 1 МБ. Колонки `ФИО`, `Должность`, `Подразделение`, `Email` и `Телефон`. Обязательна только `ФИО`. Поддерживаются английские `name`, `jobTitle`, `department`, `email` и `phone`.

В локальном сервере импорт выполняет `POST /api/v1/initiatives/{id}/imports/contacts`, защищённый CSRF, одной транзакцией в SQLite. Совпадения по email сравниваются без учёта регистра; без email — по имени, должности и отделу. Существующие контакты подключаются к проекту без перезаписи; повторная загрузка не создаёт дубли. Роли, влияние и связи не выводятся из должности. Данные об актуальности не придумываются.

В Spring Boot импорт использует тот же маршрут и проверяет `canImportContacts: true` в `/capabilities`. Для прямого соединения с CRM нужен корпоративный API.

## Рабочие сценарии из макетов

- Карточка контакта открывается отдельной страницей `#/client/{companyId}/person/{personId}?initiative={initiativeId}`. Кнопка «Открыть карточку» находится в правой панели. На странице доступны роль, область решений, интересы, источник, последняя коммуникация, зафиксированные шаги, входящие и исходящие связи с основанием, окружение на карте и переход в другие проекты того же человека.
- «Связи проектов» сравнивает две инициативы одной компании по каноническим ID участников, сохраняет отдельные роли в каждом проекте и показывает общих людей на карте.
- «Новый проект» сохраняет название, стадию, ответственного, срок и следующий шаг. «Новый участник» и «Уточнить запись» сохраняют контакты и проектную роль без вывода полномочий из должности. Влияние и подтверждённая связь требуют основания.
- «Добавить связь» сохраняет направление, тип, описание, основание и подтверждение. Дубли и связи с участниками другого проекта отклоняются.
- «Запросы» сохраняет черновики уточнений и их статус. Сообщения никому не отправляются.
- Карта переключается между людьми и отделами; выбор отдела открывает его участников. Для связей между отделами показывается число исходных связей, пунктир сохраняется, если хотя бы одна связь требует проверки. Доступны фильтры по ЛПР, позиции, роли, типу связи и остальным полям. В списке контактов — страницы по 12 записей.

Формы доступны при `canManageWorkspace: true` в `/capabilities`. Они сохраняются в Spring Boot и локальном Node/SQLite. Правка существующей связи через `PATCH /api/v1/initiatives/{id}/relationships/{relationshipId}` доступна в Spring Boot. Версия карточки защищает данные от перезаписи чужих правок.

Локальные маршруты: `POST /companies/{id}/initiatives`, `POST /initiatives/{id}/people`, `PATCH /initiatives/{id}/people/{personId}`, `POST /initiatives/{id}/relationships`, `GET/POST /initiatives/{id}/requests`, `PATCH /initiatives/{id}/requests/{requestId}` (префикс `/api/v1`). Все записи проходят общий CSRF-контроль и проверку Origin. Миграции SQLite добавляют столбцы и таблицу запросов, сохраняя существующие данные.
