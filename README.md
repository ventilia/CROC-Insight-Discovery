# KIT — KROK insight tool

KIT — платформа для управления отношениями с корпоративными клиентами. Она собирает сведения о сотрудниках компании, их ролях, связях и истории взаимодействий с КРОК.

Основной инструмент платформы — интерактивная карта клиента. На ней можно увидеть участников принятия решений, изучить их окружение и понять, с кем команде стоит продолжить общение. Встречи и договорённости сохраняются рядом с контактами, поэтому накопленные знания остаются в команде при передаче клиента другому менеджеру.

Проект находится на стадии MVP. В репозитории есть основное приложение, серверный API и автономное демо для локального запуска.

## Возможности

- **Обзор клиентов.** Компании, контакты, последние взаимодействия и сигналы, на которые стоит обратить внимание.
- **Карточка компании.** Описание клиента, подразделения, ключевые сотрудники и история работы по его проектам.
- **Карта связей.** Сотрудники и отношения между ними, выделение лиц, принимающих решения, просмотр окружения на один или два шага. Узлы можно перемещать и закреплять, карту — масштабировать и переключать в режим подразделений.
- **Профиль сотрудника.** Должность, контакты, роль в проекте, влияние с основанием, связи с коллегами и история общения.
- **История взаимодействий.** Встречи, звонки, письма, комментарии и предложения. В записи сохраняются участники, ответственный менеджер, результат и следующий шаг.
- **Поиск и фильтры.** По компаниям и людям, подразделению, должности, проектной роли, влиянию, давности общения и ответственному менеджеру.
- **Анализ отношений.** Охват ключевых участников и подразделений, непроверенные сведения и пробелы в общении. Индекс отношений рассчитывается по доступным данным и не является прогнозом сделки.
- **Работа с проектами.** Создание проектов и участников, уточнение карточек, добавление связей с основанием, сравнение общих участников двух проектов.
- **Импорт контактов.** Загрузка CSV с предпросмотром и проверкой дублей. Полноценная синхронизация с CRM пока не реализована.

В интерфейсе доступны тёмная и светлая темы. Для вопросов по клиенту или проекту предусмотрен ИИ-помощник: он работает через серверный API после подключения модели.

## Для кого

Менеджеры по продажам используют KIT для развития отношений и поиска новых точек входа. Маркетологи — для выбора контактов под конкретные коммуникации. Руководители проектов могут быстрее разобраться в структуре клиента и передать контекст другой команде, а руководители бизнеса — оценить устойчивость отношений и заметить слабые связи.

## Пример работы

1. Открыть обзор и выбрать компанию.
2. Перейти к карте, выбрать проект и найти участников принятия решений.
3. Открыть профиль сотрудника, посмотреть его роль, связи и предыдущие взаимодействия.
4. Найти важного участника или подразделение, с которым ещё не выстроен контакт.
5. После встречи записать результат, ответственного менеджера и следующий шаг.

Карточки, карта и история связаны между собой: от человека можно перейти к его коллегам, окружению на карте и другим проектам, в которых он участвует.

## Быстрый запуск

Для автономного демо нужен **Node.js 22.13 или новее** и npm. Java, Docker и отдельная база данных для этого режима не требуются.

```sh
git clone https://github.com/ventilia/CROC-Insight-Discovery.git
cd CROC-Insight-Discovery/frontend
npm ci
npm run build
npm run demo
```

Откройте **[http://127.0.0.1:5173](http://127.0.0.1:5173/)**. Чтобы остановить сервер, нажмите `Ctrl+C` в терминале.

Демо автоматически загружает вымышленные данные: 10 компаний и 21 проект. Для знакомства с основным сценарием можно открыть «Северную линию». Для просмотра большой карты — компанию «Атлас Север» и проект «Единая логистическая платформа»: в нём 540 участников и 1105 связей.

Данные хранятся в `frontend/.data/kit.sqlite`. Добавленные встречи и изменения сохраняются после обновления страницы и перезапуска сервера. Папка `.data` исключена из Git. Автономное демо не подключается к корпоративной CRM.

Подробности о портах, отдельной базе и загрузке демоданных — в [инструкции фронтенда](frontend/README.md).

## Запуск с серверным API

Серверный режим использует Kotlin, Spring Boot и PostgreSQL. Он нужен для работы через общий API, серверного разграничения доступа и подключения ИИ-помощника.

1. Подготовить **JDK 21** и **Docker с Compose**.
2. Настроить `backend/.env` и запустить бэкенд с профилем `demo` по [инструкции сервера](backend/README.md#локальный-запуск).
3. Для сохранения изменений подготовить деморедактора по той же инструкции.
4. Остановить автономный демосервер, если он запущен, и запустить фронтенд:

```sh
cd frontend
npm ci
npm run dev
```

Vite передаёт запросы `/api` серверному приложению. Настройка подключения находится на стороне сервера; пароли не включаются в клиентскую сборку.

Модель для ИИ-помощника выбирается в разделе «Настройки ИИ». Поддерживаются локальные модели и внешние провайдеры. Параметры подключения и способ передачи ключей описаны в [настройках ИИ](backend/README.md#настройки-ии). Без подключённой модели карта, история и аналитика по правилам продолжают работать.

## Как устроены данные

Компания объединяет подразделения, контакты и проекты. Сотрудник может участвовать в нескольких проектах, причём его роль, влияние и позиция хранятся отдельно для каждого из них.

Цвет узла показывает роль или подразделение — в зависимости от выбранного режима карты. Размер зависит от указанной оценки влияния. Линии сохраняют направление связи, пунктир обозначает неподтверждённую связь. Неизвестные роли и оценки остаются незаполненными: платформа не выводит их из должности сотрудника.

История общения привязана к проекту и его участникам. В карточке компании доступны взаимодействия по всем её проектам. Для рекомендаций по правилам используются записанные встречи, охват подразделений и актуальность контактных данных.

## Проверки

Фронтенд и автономный демосервер:

```sh
cd frontend
npm test
npm run build
```

Бэкенд, при установленных JDK 21 и Docker:

```sh
cd backend
./gradlew test
```

В Windows используется `gradlew.bat`. Интеграционные тесты бэкенда поднимают PostgreSQL через Testcontainers.

Тесты охватывают фильтрацию и направление связей, расчёт охвата, сохранение истории, проверку прав, повторные запросы и конфликты версий. Подробные сценарии описаны в [документации фронтенда](frontend/README.md) и [бэкенда](backend/README.md).
